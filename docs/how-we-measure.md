# 我们怎么测的（先读这篇再看任何数字）

这份文档解释本仓库所有速度结论的产生方式。**如果你想在自己的机器上复现或反驳这些数字，
先看懂这里的协议，否则很容易得出错误结论。**

---

## 核心原则：唯一变量

所有 A/B 的共同点：**同一个二进制文件**，唯一变化的是环境变量或配置 flag。
改任何东西都要重启服务（约 30 秒），重启后第一个请求含冷加载，必须先warmup 再计时。

---

## ABAB 交替协议

单次测量不可信——GPU 时钟、温度、页缓存都会漂移。我们的做法：

```
A B A B A B     每个 arm 至少 3 次
```

然后取 **best-of-N**（每组里最快的那个），并同时报告同一 arm 内的**离散度**。
`--layer-split` 那次扫描就是靠这个发现 25 和 26 只差 0.26 tok/s（平台期），
所以才敢取 25 而不是 26。

**离散度是诚实度的关键**：如果两次同 arm 差5%，那个数字就不能用来对比 2% 的差异。

## 三类测量，各有各的坑

### 1. prefill（prompt处理）— 用 `scripts/bench_prompt.py`

**关键：用唯一前缀（prompt-iso）。**

服务器有对话缓存，如果两次请求前缀相同，第二次会命中缓存，测出来的是"读缓存"的速度
而不是真实预填充速度。所以每次请求带一个唯一的短前缀（比如 `test-1702384712`），
让它无法命中缓存。

口径：**prompt tok/s = prompt token 数 / prefill 耗时**，不包含 decode 阶段。

### 2. decode（逐字生成）— 用 `scripts/bench_strata.py`

注意 decode 和 prefill 是**两个不同的瓶颈**：

- prefill 吃**算力**（矩阵乘法密集，能吃满 tensor core / MMQ）
- decode 吃**显存带宽**（每生成一个 token 要把整个模型的所有激活的专家权重读一遍）

所以**同一个改动在两个阶段的收益可能完全相反**。我们最大的 WMMA 收益（+4.2%）在 prefill，
对 decode 是零 —— 这不是 bug，是两个阶段的硬件特性不同。

### 3. 长生成 — 用 `scripts/bench_strata.py`

连续生成几千 token 看稳态吞吐。这一项会把 `--spec 8` 这类"短期快、长期慢"的改动暴露出来
（105.6→99.5 tok/s）。

## 相位表：哪一段真的变快了

如果只想知道一个改动快了多少，看端到端 tok/s 足够了。
但如果想知道**为什么快**，需要拆到内部阶段。

用 `STRATA_PREFILL_TIMING=1` 启动，引擎会打印每个请求各阶段的毫秒数：

```bash
bash scripts/pfwmma_ab_time.sh 2    # 2 = down-only 模式
```

输出形如：

| phase | ms |
|---|---:|
| gemm gate/up | 238-255 |
| gemm down | 129-131 |
| GPU timeline | 645-672 |

这就是我们发现"gate/up 慢 20% 但 down 快 20%"的地方 —— **只看端到端 tok/s 会看到"净打平"，
然后错误地得出"tensor core 没用的结论"**。拆阶段才看得见真实结构。

> 重要：相位表的第一个请求包含冷加载（内核编译、显存加载），**必须 warmup 后再读数**。

## 正确性怎么保证

速度数字谁都能编，我们要让结论经得起复核：

1. **parity 工具**：`build-cuda/pf_wmma_parity` 对 IQ3_S 1280×2560 与 IQ4_NL 2560×640的
   全部 8 个格式对比新旧内核输出（max err 1.3e-3 / 1.6e-4）。
2. **逐字节一致**：新二进制在"关闭改动"的env 下，输出与旧二进制**逐字节一致**
   （证明非目标路径零改动）。
3. **确定性重跑**：同 arm 跑两次，输出逐字节一致。

`STRATA_PF_WMMA=2` 三条全过。

## 复算清单

想知道某个数字怎么来的，你需要：

| 想复现 | 需要什么 |
|---|---|
| prefill 对比 | `scripts/bench_prompt.py` + prompt-iso + ABAB 交替 |
| decode 对比 | `scripts/bench_strata.py` + 同一 arm 多次取 best |
| 内部阶段拆解 | `STRATA_PREFILL_TIMING=1` + `scripts/pfwmma_ab_time.sh` |
| 输出正确性 | `build-cuda/pf_wmma_parity` |
| 模型结构核查 | `scripts/gguf_meta.py`（解析 GGUF 头） |

## 我们踩过的测量坑

- **对话缓存污染 prefill**：不换唯一前缀会测出缓存命中，虚高得离谱。
- **冷加载混进数据**：重启后第一个请求永远慢，warmup 是硬要求。
- **只看端到端**：两个相反方向的收益会互相掩盖（见上文 WMMA）。
- **5fresh token 批次 vs 单token**：`--short-read` 这类 flag 在不同 batch 下的结论会反转，
  所以要两种都测（`scripts/bench_shortread.py` 做判别）。
- **单次跑就下结论**：GPU 状态会漂移，ABAB 是最低要求。
- **累计值当采样值用**：`/metrics` 的 PCIe/磁盘计数器是**累计值**，必须请求前后快照差分；
  对 200ms 采样点直接求和会得出虚高一个数量级的假流量（2026-10-14 实测踩到，
  详见 [`storage-and-io.md`](storage-and-io.md) §7）。
- **并发不等于并行**：引擎对并发请求是 FIFO 串行（实测聚合吞吐不随 N 增长），
  所以「多开会话撑满 GPU」在这台机器上不成立，别把它当优化手段记。
- **隔离内核基准只能筛掉明显更差的候选，不能用来宣布收益**（2026-10-16 最硬的一次证据）：
  `STRATA_NO_MMVQ_ROWS2=1` 在隔离基准里 nc=2 **快 8.5%**、52 个输出**逐位相同**，
  端到端 decode 却**慢 5%**（101.35/103.45 vs 基线 106.75/108.4，回滚后复测基线排除重启效应）。
  **逐位相同也不能免检**——它只保证单个内核算得对，不保证它在与 MoE 计算、跨 PCIe 传输
  并发抢同一张卡时的调度特性不变（每块一行 ⇒ grid 块数翻倍，独占时免费、混跑时要付钱）。
  完整数据与机制分析见 [`window2-2b-dense-q4k-2026-10-16.md`](window2-2b-dense-q4k-2026-10-16.md) §4。
- **换量化档 = 所有内核结论作废**：同一批 dense 投影，IQ3_S 档是 Q6_K/Q4_K/IQ4_XS 混合、
  单列带宽 37–67% 峰值；换到 Q4_K_M 档全部变 Q8_0、单列 81–91% 峰值。
  「37% 带宽利用率」这个病灶直接消失，基于它立的所有优化前提同时失效。
  **换档后第一件事是重测，不是搬结论。**
