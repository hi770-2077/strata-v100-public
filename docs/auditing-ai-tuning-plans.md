# 如何审计一份 AI 生成的调优方案：14 个参数，11 个查无此物

> 缘起：2026-10-11 收到两份外部方案（一份「4 智能体 3 阶段部署方案」目标端到端 +80~120%，
> 一份「三阶算力资产化」框架）。评审依据：本机引擎 `--help`（225 行）逐条查证 + 引擎源码 +
> 官方 docs + 现网实测。**结论：战略方向有对的，具体实现几乎全是编的。**

这份文档值得公开，因为**拿 AI 生成的「优化方案」直接执行，是社区里正在发生的事**——
而里面的参数可能根本不存在。本文记录查证方法、两个物理级否决、和一个真正有价值的洞察。

---

## 一、查证方法：三步，每步都有出处

任何方案进来，先过这三步，**不过第三步的不算数**：

| 步骤 | 动作 | 本例结果 |
|---|---|---|
| 1. `--help` 逐条对 | 225 行 help 里 grep 方案写的每个 flag/env | 14 个参数里 **11 个不存在** |
| 2. 源码 `getenv` 对 | 名字对不上时，去源码里 grep 真实名字 | 编造名 vs 真名全部找到对应 |
| 3. 官方 docs 行号对 | 收益数字必须能指到官方文档的具体行 | 方案的「官方数据」多数指不到任何行 |

### 编造名 vs 真名（本例实测）

| 方案写的 | 引擎实际 | 判定 |
|---|---|---|
| `STRATA_ENABLE_SM70_OPTIMIZATION=1` | **不存在**。真名 `STRATA_SM70_TABLE`（源码 `getenv` 确认） | ❌ 编造 |
| `--mtp-mode=stream` | **不存在**。真名 `--mtp-hnorm stream` | ❌ 编造 |
| `--mtp-max-candidates=4` | **不存在**。真名 `--spec N` | ❌ 编造 |
| `--enable-flash-attention2=true` | **不存在**（`--native-flash-attn-short` 是 diagnostic 且限 `--max-context<=256`） | ❌ 编造 |
| `--kv-cache-sharding=true` | **不存在**。真名 `--kv-resident` / `--kv fp16\|int8\|q4_0` | ❌ 编造 |
| `--enable-continuous-batching=true` | **不存在**。真名 `--batch N` / `--slots N` | ❌ 编造 |
| `--max-batch-size=8` / `--batch-timeout-ms=50` / `--priority-scheduling=true` | **均不存在** | ❌ 编造 |

**这不是版本差异**——评审时本机跑的就是方案声称的那个版本。

### 反向也要查：方案没提的、真实存在的关键参数

`--kv q4_0` / `--kv int8`（比 `k8v4` 更省的 KV 量化）、`--conversation-cache-mib` / `--slots`
（多会话停驻）、`--batch-groups`（官方批处理流水线，方案的核心主张完全没提）、
`--kv-grow`、`--ple-io ram`、`--spec-min-p`。

**一份连真实参数名都列不全的方案，它的收益数字没有审计价值。**

## 二、两个物理级否决：不是"没测过"，是"不可能"

### 否决 1：「MoE 动态调专家数/层数，造四档算力模型」

方案主张「MoE 天生支持动态调整专家数和层数，不用改模型结构」——

**这句话是错的。** 查证：

1. `--help` 225 行里没有任何 `--n-expert` / `--layers` / `--early-exit` 类参数
2. 源码里层数和专家数是**加载期常量**，从 GGUF 权重读出来传给引擎，不是运行时旋钮
3. 「512 专家 top-10 路由」是**训练时决定的架构**。运行时改成 2 专家，
   等于让 510 条路径的权重完全失效——**不是"低配模式"，是残废模型**

> 方案自己的验收标准「草稿档速度 ≥2.5 倍」倒是真能达成——用一段残缺模型跑当然快，
> 但输出一片胡话。**能跑分和能用是两回事。**

### 否决 2：「沉淀中间计算态，只算差异部分，节省 40~70%」

引擎有 `--dump-layers` / `--dump-halves` / `--dump-residual` / `--dump-routing`，
但**全是「导出诊断用」，没有「导入并复用」的接口**。

数学上也不成立：中间层表征是**位置相关**的——同一句"苹果"在第 5 层和第 30 层的向量完全不同，
因为它经过了前面所有层的变换。**在带路由的非线性堆叠里，"只算增量"没有对应的数学结构。**

## 三、一个真正危险的提案：「语义相似就复用缓存」

方案说「从完全一样的 prompt 才复用，升级成语义相似就复用，命中直接返回结果」。

**「相似就返回结果」对 Agent 任务是系统性错误源。** Agent 任务的特点恰恰是每一步都不同：
改一个文件、换一个路径、调一个参数——prompt 语义上"高度相似"，但正确答案完全不同。
按相似度返回历史结果，等于**系统性地给出错误答案，而且这种错误很隐蔽**（看起来答得挺像）。

**正确的形态是精确复用，不是相似复用**：请求体里声明
`"strata_prefix": {"messages": 1}`，引擎钉住文档边界，之后每个问题从文档末尾续读——
20 个问题只读一次文档，**零质量风险**。完整数据见
[`client-call-patterns.md`](client-call-patterns.md)。

## 四、本次评审认下的真洞察：「消耗型 vs 资产型优化」

方案提出的这个区分是**真洞察**，而且指出了我们全部工作的真实天花板：

- 我们当时所有成果（破 200 decode、prefill +53%、加载 −38%）**全是消耗型优化**——
  都在「让单次计算更快」
- 而单次计算的效率上限由 sm_70 的 kernel 效率决定，**这条路确实接近走完了**
- 真正的下一层是**资产型**：让计算成果可复用——前缀缓存、会话停驻、多实例分层

这个框架与 [`methodology.md`](methodology.md) 里的「1+1>2 乘法结构」是同一件事的两种说法：
内核优化作用于「单次计算成本」（分子），前缀复用作用于「计算发生次数」（分母），数学上相乘。
底层全优化完之后，上层仍能带来 TTFT 12.4×——**底层再快也要付首轮的钱**。

## 五、裁决汇总与正确替代

| 方案主张 | 裁决 | 真实可用的替代 |
|---|---|---|
| 语义相似就复用结果 | ⚠️ 方向对，实现危险 | `strata_prefix` 固定共享前缀（精确复用）+ `conversation-cache` |
| MoE 动态调专家数/层数做算力阶梯 | ❌ 物理不存在 | **多实例分层**（小模型顶高频流量，大模型留硬任务），零模型结构改动 |
| 中间计算态沉淀复用 | ❌ 引擎无导入接口，数学基础不成立 | 长对话靠 prompt-cache / conversation-cache（精确的那部分） |
| 并发 8 请求吞吐 +40% | ❌ 与官方文档相反 | 槽内默认不带 MTP 草稿（官方 BATCHING.md 原文），开 `--batch` 等于废掉投机解码；`--batch-mtp` 不支持 layer-split。我们实测 1→4 并发总吞吐严格均分，是排队模型 |
| 语义缓存接向量数据库 | ⚠️ 对 Agent 危险 | 相似≠等价；引擎自带的精确前缀复用更安全 |

**方案里唯一该保留并落地的一条**：多实例分层。小模型实例顶高频 Agent 流量、
大模型留给硬任务——**不用动任何模型结构，零质量风险**。这才是「算力按需分配」的正解。

## 六、可复用的审计清单

下次再收到一份 AI 生成的方案，按这个过：

1. ☐ 每个 flag / env 名，`--help` 里能 grep 到吗？（grep 不到 = 编造，去源码找真名）
2. ☐ 每个收益数字，能指到官方 docs 的具体行或可复现实验吗？
3. ☐ 方案要改的东西，是**运行时参数**还是**加载期常量 / 训练期架构**？（后者免谈）
4. ☐ 涉及缓存的：**精确匹配还是相似匹配？**（相似匹配对 Agent 是错误源）
5. ☐ 涉及并发的：官方文档对默认行为怎么说的？（别信"批处理一定更快"）
6. ☐ 方案的版本号，和你要执行的引擎版本是同一个吗？
7. ☐ 看完 [`flag-ledger.md`](flag-ledger.md)——里面 10 条证伪项，是不是和你手上的方案撞了？

## 七、一句话

**方案的战略框架（分层调度、缓存资产化）可以听；方案的每一个参数、每一个数字，
都必须回到 `--help`、源码和官方 docs 上重新出生一次。**

**An AI-generated tuning plan is a hypothesis list, not an instruction list.
Every flag name and every number in it is born again — or dies — at `--help`.**
