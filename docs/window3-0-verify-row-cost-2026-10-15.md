# 窗口 ③-0：验证窗口的边际行成本（2026-10-15）

> 承接窗口 ④-1 的发现：`ms/窗 ≈ 11.5 + 4.83×(T−1)`，投机解码的收益被"每多一行 4.8 ms"吃掉。
> 本轮用引擎自报的逐窗账（`STRATA_DECODE_TIMING=1`）把这笔钱拆开。
> **结论：这 4.5 ms/行 全是 `verify`，草稿层是 0.00 ms（被 `--pipeline-windows 2` 完全流水化）。**
> 于是问题从"怎么让草稿更便宜"变成"**怎么让一个验证行更便宜，或者让每窗固定开销更小**"。

---

## 1. 方法：让引擎自己报逐窗账

`STRATA_DECODE_TIMING=1`（`generate.cpp:9971`）会在**每个请求结束时**往引擎 stderr 打一行：

```
strata decode timing: <windows> windows, avg T <T>, <tokens>/window, <ms>/window =
  verify <ms> (GPU-reach wait + per-layer host [plan/actq/jobs/CPU] + stage)
  + commit/emit <ms> + draft <ms>; per layer-window: CPU experts, VRAM hits, PCIe
```

关键：它直接给 `avg T`（**不用再从 `predicted_n − accepted` 反推窗口数**），并且把 `draft` 单列。

配合**按请求的 `strata_tune.spec_min_p`**（它决定窗口大小 T），**一次重启就能扫出整条 T 曲线**。
用可移除的 systemd drop-in `/etc/systemd/system/strata-sc117.service.d/10-timing.conf` 打开，测完即删。

## 2. 实测（同一条中文 prompt，max_tokens 400，greedy）

|---|---|---|---|---|---|---|---|

| 0.90 | 1.89 | 1.76 | 16.36 | 16.36 | **0.00** | 0.00 | 107.6 |

### 2.1 成本模型（最小二乘，6 点，残差 <0.4 ms）

```
ms/窗 = 7.79 + 4.49 × T
         └─固定─┘   └每行─┘
```

- T=1 → 12.3 ms（与 ④-1 实测的 min_p=1.0 不投机 11.5 ms 吻合）
- T=2.22 → 17.76 ms（实测 17.80）✓
- T=3.98 → 25.66 ms（实测 25.41）✓

**固定开销 7.79 ms/窗 + 每行 4.49 ms。**

### 2.2 最大发现：`draft = 0.00`

六个点全是 0.00。`--pipeline-windows 2` 把 MTP 链完全流水化（独立高优先级流），
**草稿层的耗时被 verify 完全遮住，不占窗口墙钟**。

⇒ ④-1 里"每多一个草稿 ~4.4 ms"的说法要修正：**那 4.49 ms 是验证窗口多出来那一行的成本，不是草稿层的成本。**
草稿层是免费的（在本配置的流水线深度下）。

### 2.3 因此：T≈2.2 是硬最优点

- 平均产出率：1.96 / 17.80 = **0.110 token/ms**
- 边际产出率：(2.55−1.63)/(3.98−1.70) = **0.404 token / 行**，即 0.404 / 4.49 = **0.090 token/ms < 0.110**

边际低于平均 ⇒ 加行不划算，实测 tok/s 曲线也在 T=2.22 见顶（110.1）。
要让 T=4 反超 T=2.22，需要 `2.55/(7.79+4X) > 1.96/(7.79+2.22X)` ⇒ **每行成本 X < 2.11 ms（要降 53%）**。

## 3. 这笔钱花在哪

| 组成 | 估算 | 依据 |
|---|---|---|
| **固定 7.79 ms/窗** | dense 权重读 ≈3.2 GB ÷ ~411 GB/s | `decode-budget-2026-10-14.md`：每 token dense ~3.2 GB、有效带宽 ~450 GB/s；3.2/7.79 = 411 GB/s，对得上 |
| **每行 2.1 ms** | 该行自己的 top-10 专家读 0.95 GB ÷ 450 GB/s | 同上：专家 48 层×top-10×1.97 MB = 0.95 GB/token，且**逐行不共享** |
| **每行 ≈2.4 ms** | 注意力 + GDN 递归 + MoE combine + 归一化 + head | 残差项，**未命名** |

⇒ **固定 7.79 ms 占生产窗口的 44%，是最大单项，而且跟 T 无关 —— 无论投机怎么调它都在。**

## 4. 结论与优先级（更新）

1. **窗口 ② 重新成为唯一主线**：把有效带宽从 ~411–450 GB/s 提上去，直接砍固定 7.79 ms。
   - → 615 GB/s：固定 5.5 ms，窗口 15.5 ms，**126.7 tok/s（+15%）**
   - → 720 GB/s：固定 4.7 ms，窗口 14.7 ms，**133.7 tok/s（+21%）**
   （单卡峰值实测 859 GB/s，即当前只跑到约 50%，理论上有 2× 空间。）
2. **每行 2.1 ms 的专家读**：窗口 ② 的 iq_mmvq 深度优化同一目标，若能 −30% → 每行 −0.63 ms → 生产窗口 −1.4 ms → **+8%**。
3. **每行 ≈2.4 ms 的"其他"**：**未命名，是下一步要量清楚的东西**。候选：GDN 递归（逐位置串行）、indexer scores+topk、MoE combine、head。
   要命名它，需要 `STRATA_VERIFY_PROFILE=1` 在两个不同 T 下各取一份相位报告并相减（该剖析器会关掉 shared-expert 分支和 df_branch，绝对值不可信，但**两次之间的差**可用）。
4. **窗口 ④ 已闭合**：草稿层流水化后零成本，准确率 p1≈0.83 与参考同档，min_p 上行（0.85/0.90/0.95）和下行（0.65/0.5）都更慢 —— **0.8 是峰值，flag 空间已穷尽**。
